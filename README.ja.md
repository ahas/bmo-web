# web

Web コンソール `bmo-web` です。言語パックを備えた sumida ベースのアカウントサービスであるサーバーと、人がサインイン
する Nuxt コンソールであるクライアントから成ります。コンソールの画面は各ユニットの HTTP API を呼び出します。
アカウントモデル、権限、そしてルームに定型文で伝える言葉はこのリポジトリが持ち、HTTP で他のユニットに提供します。
言語パックを持つリポジトリはここだけです。他のユニットはすべて英語のメッセージとコードで応答し、それをこのパックが
表示用の言葉に変換します。

## 構成

| フォルダ | 内容 |
|---|---|
| `server/` | サーバー: sumida ベースのアカウントサービス(`src/`。デプロイのルールファイル、ルート、チェック、権限、データ移行、電話のキー、receiver ポート、設定、定型文のレンダラー、ドキュメントの文言ファイル、`src/migration/` 配下のマイグレーション、`src/lang/` 配下の言語パックの部品を含む)、`src/bin/` 配下のバイナリ、`client/` 配下のサービス自身の契約とクライアントクレート、言語ごとに一フォルダの `lang/` 配下の言語パックファイル、サーバーと sumida の設定、そして `tests/` 配下のテストと `tests/fixtures/` 配下のフィクスチャ |
| `client/` | コンソール。独自のロックファイルを持つ独立した Bun ワークスペースで、`apps/web/` 配下の Nuxt アプリ、サーバーの OpenAPI ドキュメントから生成した `packages/server-client/` 配下の TypeScript パッケージ、`tests/` 配下のコンソールのテストと `tests/support/` 配下の補助コード、`vendor/` 配下の bmo-ui のリリースファイル、パッケージ化した bmo-text、コンソールが呼び出すユニットのパッケージ化したクライアント、そしてインストール時に当てる `patches/` 配下のパッチ |
| `tests/` | リポジトリ全体にわたるチェック: 依存関係、韓国語、構成、名前、個人データのパターン(`docs/checks.md`)。サーバーのクレートがテストハーネスの `repository` モジュールとして実行する |
| `deploy/` | デプロイがリンクするユーザーユニット: サーバーの `bmo-web-server.service` とコンソールの `bmo-web.service` |
| `.cargo/` | このチェックアウトの Cargo 設定: git 依存である sumida を git プログラム経由で取得する |
| `docs/` | コンソールとサーバーの動作を定める正典ドキュメント、そしてこのリポジトリの分離元である単一リポジトリから引き継いだものの一覧 |

ルートには、`server/` と `server/client/` をメンバーとする Cargo ワークスペースのマニフェストとそのロックファイル、
`testbed.toml`(このリポジトリのテスト、チェック、ビルド、デプロイの方法を示すテストベッドの
宣言)、`install.toml`(新しいマシンへのインストールに必要なものを記した、テストベッドの install 動詞が読む宣言)、`rustfmt.toml`、`LICENSE`(MIT)、`PERSONAL-DATA.md`(どのファイルにも置いてはならない個人データ)、
`WORDING.md`(コンソールが表示する韓国語のガイド)、`CLAUDE.md`、そして `korean-ledger.json`(コードファイルに
残る韓国語の台帳で、テストベッドの韓国語スイープがすべてのファイルをこれと突き合わせます。このリポジトリのコード
ファイルには韓国語は一切ありません)があります。

| `docs/accounts.md` | アカウントサービス: 何を保持するか、どこで応答するか、モデルがいつ有効になるか、ルート、コマンド、テーブル |
| `docs/language-pack.md` | 言語パック: サーバーのパックとコンソールのパック、それぞれの読み方、そして他のユニットが読む部分 |

## バージョン

- **バージョンはセットのものです。** ビルド時に git タグから読み取り、テストベッドがそれを `BMO_VERSION` として
  ビルドに渡し、サーバーのヘルスがそれを答えます。マニフェストのバージョン欄は動かないプレースホルダーです。
- **バージョンはオーナーが宣言したリリースでのみ変わります。** bmo-chat の `docs/conventions.md` 「Versions」に
  あるとおりです。コミット、デプロイ、修正、契約の変更ではバージョンは変わらず、デプロイはコミットで区別します。

## チェック

`bmo-testbed check quick` は、何かを実行する前にツリーを読むスイープを実行します。コード中の韓国語、README の
フォルダ表、マニフェストが挙げる依存関係、Cargo プロファイル、共有バージョンです。他のリポジトリからの依存は、
基盤ライブラリの `bmo-chat`、`bmo-chat-client`、`bmo-ui`、`bmo-text` と、コンソールが呼び出すユニットが公開
しているクライアント `@agency/client`、`bmo-job-client`、`@bmo/receiver-client` だけで、`testbed.toml` に宣言
されています。コンソールはインストールするものを `client/vendor/` 配下のファイルから取り込み、bmo-ui はリリース
コマンドが書き出したままのものを使います。`shared-versions` スイープは、そのファイルが bmo-chat の共有バージョンが
固定するリリースと一致することを確かめます。サービス自身のクライアントクレート `bmo-web-client` と、そこから生成した
パッケージ `@web/server-client` はこのリポジトリ自身のもので、どのユニットのパッケージでもありません。`client/` で
`bun run typecheck` を実行すると、コンソールアプリ、生成された TypeScript パッケージ、コンソールのテストを
チェックします。
