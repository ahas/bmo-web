# web

웹 콘솔 `bmo-web`입니다. 언어 팩을 갖춘 sumida 기반 계정 서비스인 서버와, 사람이 로그인하는 Nuxt 콘솔인
클라이언트로 이루어집니다. 콘솔의 화면은 각 유닛의 HTTP API를 호출합니다. 계정 모델, 권한, 그리고 방에 정해진
문구로 전하는 말은 이 저장소가 소유하며, HTTP로 다른 유닛에 제공합니다. 언어 팩을 가진 저장소는 이곳 하나뿐입니다.
다른 모든 유닛은 영어 메시지와 코드로 답하고, 이 팩이 그것을 사람이 읽을 말로 바꿔 보여 줍니다.

## 구성

| 폴더 | 내용 |
|---|---|
| `server/` | 서버: sumida 기반 계정 서비스(`src/`. 배포의 규칙 파일, 라우트, 검사, 권한, 데이터 이전, 휴대폰 키, receiver 포트, 설정, 정해진 문구의 렌더러, 문서 문구 파일, `src/migration/` 아래의 마이그레이션, `src/lang/` 아래의 언어 팩 구성 요소를 포함), `src/bin/` 아래의 바이너리, `client/` 아래의 서비스 자체 계약과 클라이언트 크레이트, 언어별로 한 폴더씩 둔 `lang/` 아래의 언어 팩 파일, 서버와 sumida의 설정, 그리고 `tests/` 아래의 테스트와 `tests/fixtures/` 아래의 픽스처 |
| `client/` | 콘솔. 자체 lockfile을 가진 독립 Bun 워크스페이스로, `apps/web/` 아래의 Nuxt 앱, 서버의 OpenAPI 문서에서 생성한 `packages/server-client/` 아래의 TypeScript 패키지, `tests/` 아래의 콘솔 테스트와 `tests/support/` 아래의 보조 코드, `vendor/` 아래의 bmo-ui 릴리스 파일, 패키징된 bmo-text, 콘솔이 호출하는 유닛들의 패키징된 클라이언트, 그리고 설치 시 적용하는 `patches/` 아래의 패치 |
| `tests/` | 저장소 전체에 걸친 검사: 의존성, 한국어, 구성, 이름, 개인정보 패턴(`docs/checks.md`). 서버 크레이트가 테스트 하네스의 `repository` 모듈로 실행 |
| `deploy/` | 배포가 연결하는 사용자 유닛: 서버의 `bmo-web-server.service`와 콘솔의 `bmo-web.service` |
| `.cargo/` | 이 체크아웃의 Cargo 설정: git 의존성인 sumida를 git 프로그램으로 가져옴 |
| `docs/` | 콘솔과 서버의 동작에 대한 기준 문서, 그리고 이 저장소가 분리되어 나온 단일 저장소에서 가져온 것의 목록 |

루트에는 `server/`와 `server/client/`를 멤버로 둔 Cargo 워크스페이스 매니페스트와 그 lockfile, `VERSION`의 버전,
`testbed.toml`(이 저장소를 어떻게 테스트·검사·빌드·배포하는지에 대한 테스트베드 선언), `install.toml`(새 기계에 설치할 때 필요한 것을 적은, 테스트베드의 install 동사가 읽는 선언), `rustfmt.toml`,
`LICENSE`(MIT), `PERSONAL-DATA.md`(어떤 파일에도 들어가면 안 되는 개인정보), `WORDING.md`(콘솔이 보여 주는
한국어에 대한 가이드), `CLAUDE.md`, 그리고 `korean-ledger.json`(코드 파일에 남은 한국어 기록으로, 테스트베드의
한국어 점검이 모든 파일을 이것에 비추어 확인합니다. 이 저장소의 코드 파일에는 한국어가 하나도 없습니다)이 있습니다.

| `docs/boundary.md` | 경계: 서버가 제공하는 모든 라우트, OpenAPI 계약과 생성된 클라이언트, 서버와 콘솔이 다른 유닛에 하는 모든 호출, 그 유닛들을 지정하는 설정, 그리고 팩이 렌더링하는 코드 |
| `docs/accounts.md` | 계정 서비스: 무엇을 보관하는지, 어디서 응답하는지, 모델이 언제 적용되는지, 라우트, 명령, 테이블 |
| `docs/language-pack.md` | 언어 팩: 서버의 팩과 콘솔의 팩, 각각을 읽는 방법, 그리고 다른 유닛이 읽어 가는 부분 |
| `docs/web.md` | 콘솔: 레이아웃, 모션, 접근, 문구, 모든 화면, 알림, 유닛과의 통신, 설정과 실행 방법 |
| `docs/documents-viewer.md` | 문서 뷰어: 루트, 이름과 버전, 경로 경계, 조각, 목차, 구절에 대해 묻기 |
| `docs/skeleton-loading.md` | 아직 가져오는 중인 콘텐츠의 자리를 콘솔이 유지하는 방법 |
| `docs/checks.md` | 테스트 스위트가 테스트(브라우저 테스트 포함)를 실행하는 방법. 저장소 전체에 걸친 검사: 패키지와 코드가 의존해도 되는 것, 코드와 테스트에 한국어 금지, 구성, 추적되는 어떤 파일도 일치하면 안 되는 개인정보 패턴, 그리고 추적되는 어떤 파일에도 있으면 안 되는 이름 |
| `docs/inventory.md` | 이 저장소가 분리되어 나온 단일 저장소의 모든 구성원: 여기서 어디에 있는지, 그것을 옮긴 작업, 그리고 옮겨 오지 않은 것을 소유한 유닛 |

## 버전

- **저장소 전체에 버전은 하나입니다.** `VERSION`에 들어 있으며, 서버와 클라이언트의 매니페스트 버전도 이와
  같습니다.
- **버전은 소유자가 선언한 릴리스에서만 바뀝니다.** bmo-chat의 `docs/conventions.md` 「Versions」에 적힌
  대로입니다. 커밋, 배포, 수정, 계약 변경은 버전을 바꾸지 않으며, 배포는 커밋으로 구분합니다.

## 검사

`bmo-testbed check quick`은 무언가를 실행하기 전에 트리를 읽는 점검을 실행합니다. 코드 속 한국어, README의 폴더
표, 매니페스트가 지정한 의존성, Cargo 프로필, 공유 버전입니다. 다른 저장소에서 가져오는 의존성은 기반 라이브러리
`bmo-chat`, `bmo-chat-client`, `bmo-ui`, `bmo-text`, 그리고 콘솔이 호출하는 유닛들이 공개한 클라이언트
`@agency/client`, `bmo-job-client`, `@bmo/receiver-client`뿐이며, `testbed.toml`에 선언되어 있습니다. 콘솔은
설치하는 것들을 `client/vendor/` 아래의 파일에서 가져오고, bmo-ui는 릴리스 명령이 쓴 그대로 가져옵니다.
`shared-versions` 점검은 그 파일이 bmo-chat의 공유 버전이 고정한 릴리스와 같은지 확인합니다. 서비스 자체의
클라이언트 크레이트 `bmo-web-client`와 그로부터 생성한 패키지 `@web/server-client`는 이 저장소의 것이며, 어떤
유닛의 패키지도 아닙니다. `client/`에서 `bun run typecheck`를 실행하면 콘솔 앱, 생성된 TypeScript 패키지, 콘솔
테스트를 검사합니다.
